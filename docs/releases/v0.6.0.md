# PVM Runtime 0.6.0 — Public Preview

[简体中文](v0.6.0.zh-CN.md)

PVM Runtime 0.6.0 turns the previous runtime baseline into a package that can
be evaluated in existing applications: selective legacy migration, a portable
desktop migration application, incremental native rendering on all three mobile
platforms, and a GitHub-backed project website are now delivered together.

## Highlights

### Selective legacy migration

- Scan and convert one class, multiple selected classes, one module, multiple
  modules, or a combined selection without modifying the source project.
- Produce reviewable DSL scaffolds plus a machine-readable migration report.
- Block acceptance when the source snapshot drifts, review items remain open,
  capabilities are unapproved, DSL structure is invalid, or behavior probes do
  not match.

### PVM Migration Studio

- A C++17/Qt desktop workflow for Scan → Convert → Review → Verify.
- Portable packages for Windows x64, macOS Apple Silicon, and macOS Intel.
- Embedded migration backend, C++17 verifier, required licenses, logs, progress,
  and an output directory that remains separate from the legacy project.

### Incremental native rendering

- UI Wire v2 emits versioned patches while C ABI v1–v3 retain complete-tree
  compatibility.
- Android reuses RecyclerView rows, iOS updates UICollectionView/UIKit/SwiftUI
  nodes, and HarmonyOS applies keyed ArkUI mutations.
- Hosts coalesce render work, reject stale revisions, discard late callbacks,
  and keep VM evaluation away from the platform main thread.
- Platform performance gates cover incremental updates, full rebinds, list
  reuse, and main-thread bookkeeping.

### iOS lifecycle recovery

- The Demo now uses UIScene lifecycle integration and restores persisted VM
  state after a real background/termination/relaunch sequence.
- Automated Simulator verification covers counter, text input, async state, and
  state restoration.

### Project distribution and community

- Precompiled Android AAR/Maven, iOS XCFramework/Binary Swift Package, and
  HarmonyOS HAR remain available without compiling the Runtime source.
- The Release now includes a directly installable, debug-signed Android Demo
  APK for evaluation.
- The repository has a bilingual contribution path, Code of Conduct,
  Discussions, topics, social preview asset, and a dependency-free GitHub Pages
  website.

## Compatibility

- Runtime 5 and PVBC v5 remain the current format; this release does not bump
  the bytecode format.
- Runtime 5 continues to read PVBC v1 through v5.
- Mobile C ABI v4 selects UI Wire v2; C ABI v1–v3 keep complete-tree delivery.
- Android Runtime minimum SDK is 24; the standalone Demo minimum SDK is 33.
- The iOS binary SDK targets iOS 15 and contains arm64 device plus arm64/x86_64
  Simulator slices.
- The HarmonyOS HAR is compatible with API 23 and built with DevEco API 24.

## Verification

The release commit must pass the core, Android, Apple, KMP, container, website,
and desktop packaging workflows. SDK archives include SHA-256 checksums. The
Android Demo APK in this release uses the Android debug key and is intended for
evaluation; production applications should consume the Runtime SDK and use
their own application identity, embedded module, permissions, and signing.
